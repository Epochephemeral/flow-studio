# Node 与 Flow

Flow Studio 帮助读者看清系统为什么有这组处理、每个处理负责什么、它们如何依赖，以及这些描述有什么依据。顶层对象是 Node 和 Flow；端口、来源、Prompt 与触发说明附着在它们上面。

## Node：按责任划分执行单元

Node 有明确的职责、输入、输出和启动条件。粒度以能独立解释责任为准：一个节点可以是一次调用，也可以是固定的多步编排。函数数、模型调用数和服务部署数都不直接决定节点数。

| 属性 | 含义 |
| --- | --- |
| 稳定 ID | 连接和共享使用的身份，展示名称可以变化 |
| purpose | 节点负责完成什么 |
| type | 谁决定处理步骤与下一步 |
| implementation | 引用的实现能力及配置 |
| inputs / outputs | 具名数据契约和输入来源 |
| trigger | 什么时候开始、依赖什么条件 |

Node 是定义中的责任位置，所引用的执行能力可以被多个 Node 复用。复用同一个 API、函数或模型，不代表共享同一处处理；分别消费不同输入的处理应使用不同节点 ID。

### program、model 和 harness

| 类型 | 判定依据 | 示例 |
| --- | --- | --- |
| program | 步骤和下一步由代码决定 | 校验、下载、固定安排两次模型调用后合并结果 |
| model | 在固定调用契约内判断或生成，宿主消费结果 | 分类、抽取、视觉判断、embedding |
| harness | 根据目标和观察动态选择行动及停止时机 | 在工具、权限和预算约束内调查材料的 Agent |

程序内部包含模型调用，仍可以是 program。模型供应商、名称和参数属于实现配置，不改变类型。模型节点也未必使用文本 Prompt。

Harness 对外声明目标输入、产物和能力边界，内部行动由实现承担。图展示它可做什么、受什么限制；一次具体运行选择了哪些工具，需要由运行记录证明，不能把可能的工具调用提前画成必经步骤。

## 输入与触发分开表达

输入回答“使用什么”，触发回答“什么时候开始”。输入可以来自外部、配置引用或另一个节点输出。跨节点引用使用节点 ID 和输出名，不通过展示名称猜测。

一个输出可以被多个节点消费。数据契约保留结构、必填性和数量关系：`Document` 和 `Document[]` 不自动互换。筛选、拆分、合并与格式转换应由有明确责任的节点解释。

数据边由输入绑定派生；前置完成等控制依赖属于触发语义。成员关系和画布位置都不产生依赖。边不需要独立身份或生命周期。

定时、外部请求、输入就绪、前置完成和结果条件都可能决定启动。声明这些事实，不等于已经定义一个完整调度语言。

条件路径应保留条件文本。音频走转写、纯文本直接进入正文解析时，两条连线不表示必须同时完成。开放语义判断由模型或 Harness 给出结构化结果，后续条件消费该结果；图不替宿主实现判断与调度。

## Flow：为目的组织节点的平级视角

Flow 定义目的、节点集合和与目的直接相关的输出。`results` 解释它交付什么，不表示某次运行已经完成。

- Flow 之间没有父子或大小关系。
- 一个 Node 可参与多个 Flow；成员关系不是节点所有权。
- 同一 ID 表示共享同一处处理，多选 Flow 时只绘制一次。
- 跨 Flow 输入直接引用来源 Node 的输出，不增加一层 Flow 端口别名。
- 成员关系不生成依赖，也不意味着启动一个 Node 会启动整个 Flow。

例如，“文档准备”和“摘要”都引用同一个全文解析节点，组合后该节点仍只有一个身份。两个节点即使调用相同的摘要函数，只要分别处理不同输入，就应保留各自的 ID。

## 观看范围与定义分开

选中一个 Flow 后，它的输入和去向可能超出成员集合。关联边界展示直接上下游，并标明哪些节点在当前范围之外；进一步展开由读者控制。

聚焦保留选中节点及一跳上下游，未展开的邻接关系以数量提示。关闭聚焦恢复所选 Flow 的范围。图和关系表读取同一批关系数据，共享选择与定位。

Flow 选择、节点位置、布局方向、面板宽度和颜色属于观看状态。拖拽和聚焦只改变如何阅读，不改变节点定义、连接或执行行为。

## 来源、配置与真实执行分别说明

定义解释系统应如何工作，配置说明指定版本采用什么策略，运行记录证明某次实际发生了什么。三者不能互相代替。

源码引用保留路径、行号和内容哈希。Prompt 展示原文及组合来源，并说明模板变量、动态 schema、运行输入与当前配置的读取范围。已知材料未取得时保留配置引用和定位依据，不补造正文。

源码中的默认 Prompt 或静态配置只证明该定义存在。它是否正在生效，需要对应配置版本的证据；模型是否调用成功，需要执行证据。一次源码版本也不能替代对工作区修改和外部配置的说明。

## 当前快照的表达边界

v1 的具体字段见 [快照格式](snapshot-format.md)：节点输出绑定和外部输入是结构化字段；配置引用、启动方式、权限和预算通过实现引用、说明与 Prompt 材料表达。触发条件目前是阅读文本，控制依赖没有独立的机器可读字段，也不自动生成控制边。

`schema` 是展示用契约名称。校验会检查 ID、端口、成员和结果引用，但不会推断两个不同类型是否兼容，也不承担运行时数据校验。未声明 Prompt 不意味着节点属于程序；未知材料用缺失声明呈现。

数据关系可以包含反馈。布局不证明关系无环；跨节点循环成为可执行协议之前，需要明确每次迭代的输入、状态及停止条件。静态阅读器保留来源中的事实，不为了布局方便改变系统语义。

## 用这些判断检查扩展

1. 名称改变后，稳定 ID、共享关系和连接仍成立。
2. 代码固定安排多次模型调用，仍可作为 program；下一步由目标与观察动态决定时才是 harness。
3. 没有文本 Prompt 的模型调用，仍能作为 model。
4. 同一节点参与多个 Flow，只增加观看视角；复用实现但输入独立时，保留不同节点。
5. 一条输入带条件，不会被解释为所有输入都必须同时就绪。
6. 配置或 Prompt 正文未知时，界面保留未知及来源，不将其显示为已加载。
7. 图上出现节点、Prompt 或连线，不构成执行成功的证据。
